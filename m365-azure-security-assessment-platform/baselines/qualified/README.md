# Qualified Baseline Pack Candidate

`pack-0.1.1.json` is the current pending-review pack candidate, pinned by `freeze-manifest-0.1.1.json`. The existing `control-inventory.json` and synthetic customer fixtures are unchanged. The candidate preserves all 13 stable control IDs, inventory requirements, source references, service support gaps, and traceability to the service-assessment scenario, implementation task, and fixture family.

Version 0.1.1 corrects only PP-001's coverage rule to match design section 6: `expected_environment_ids` must equal the independently approved `environments` inventory and be a subset of `covered_environment_ids`. Extra covered environments are allowed; missing expected environments, inventory, or collection coverage cannot pass. DLP must still be enabled and prohibited connector-pair tests must still match the approved blocked-pair inventory. Public source pins, review states, and operation qualification are unchanged. Qualified acceptance definitions are explicitly synthetic and test-only, not source review, API qualification, or production approval.

Version 0.1.0 remains frozen history: `pack-0.1.0.json` and `freeze-manifest-0.1.0.json` are unchanged. That version required covered environments to equal the expected inventory; it is retained rather than rewritten. The acceptance project now copies and tests version 0.1.1.

The recorded `sourceRevision` is `sha256:<responseSha256>` over the bytes actually downloaded from the public source page. It is a reproducible retrieval pin, not a publisher-issued semantic version, git commit, or claim that the source recommends the candidate value. Source content is not bundled. Microsoft/CISA are recorded as technical-source classifications; CIS rights are not presumed and CIS benchmark text is not included; applicable SANS policy controls remain manual. Every source and control is pending human review, all controls remain `manual/unverified`, and no source-specific API operation is enabled.

Expected-state notes distinguish customer-policy candidates from unresolved source mappings. In particular, the Defender for Cloud Apps source page named in the design returned 404; a live Conditional Access app-control page does not justify the governance-policy coverage rule. The three failed original URL retrievals are recorded in `../reviewed-sources/source-discovery-failures.json`, with error-response hashes explicitly excluded from source revisions.

Pack publication is not activation. A changed pack requires a new semantic version; the in-process catalog rejects changed content under an existing version. Source updates create pending review notices with hash/HTTP-metadata differences only and cannot activate a release. Source page text is not retained, so a reviewer must inspect the pinned public page and record a rights-safe human summary before approving a source change; this implementation does not claim a full-text diff. Platform, MSP, and customer layers resolve in order, incompatible values require an explicit approved conflict choice, and activation requires an approval bound to the exact pack/profile hash and tenant scope. No persistent catalog or API wiring is included in this owned slice.
